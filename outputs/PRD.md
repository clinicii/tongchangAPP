# 同场 App 产品需求文档（PRD）

- **产品名称**：同场
- **产品定位**：面向年轻人的活动发现与兴趣社交 App，帮助用户发现演唱会、展览、Livehouse 等活动，找到同场搭子，并在活动后持续分享和建立关系。
- **文档版本**：v1.0
- **文档状态**：第一版开发依据
- **目标平台**：手机优先的响应式 Web App，可进一步封装为 Android / iOS 应用

---

## 1. 产品目标

### 1.1 核心目标

让用户完成完整闭环：

```text
发现活动 → 查看详情 → 找同场搭子 → 聊天确认 → 一起参加 → 发布体验 → 建立长期搭子关系
```

### 1.2 产品价值

- 降低一个人参加活动的心理门槛。
- 根据活动、时间和兴趣帮助用户匹配合适的同行者。
- 让活动结束后的体验、评价和关系继续沉淀。
- 通过圈子信息流形成持续的兴趣交流。

### 1.3 第一版目标

第一版需要完成：

- 发现页活动推荐与分类浏览。
- 搜索活动并查看搜索结果。
- 活动详情和活动相关内容。
- 针对具体活动发起找搭子流程。
- 匹配结果中的多位独立搭子详情。
- 与搭子聊天和发送活动卡片。
- 圈子推荐信息流、关注信息流和帖子互动。
- 发布活动体验或找搭子内容。
- 我的主页编辑、活动记录和历史搭子。
- 消息、通知、夜间模式、护眼模式和基础设置。
- 本地数据保存、备份、恢复和版本更新提示。

## 2. 使用场景

### 场景 A：用户想找演唱会搭子

1. 用户打开发现页。
2. 在活动分类中选择“演唱会”。
3. 浏览热门活动轮播和活动列表。
4. 点击某张活动卡片。
5. 在活动详情中查看时间、地点、相关帖子和参与人数。
6. 点击“找同好”。
7. 设置同行方式、社交状态、到场时间和关系期待。
8. 点击“开始匹配”。
9. 查看小满、阿树、Yuki 三位独立推荐搭子。
10. 点击任意一位进入对应的搭子详情。
11. 点击“和 TA 同场”或“发起聊天”。
12. 在聊天中发送文字和活动卡片。
13. 对方确认后，活动状态变为“已确认同行”。

### 场景 B：用户想看展览推荐

1. 用户在发现页点击“展览”。
2. 首页轮播和列表切换为展览内容。
3. 用户点击搜索栏搜索展览名称或展馆。
4. 搜索结果显示活动、帖子和用户。
5. 点击活动结果进入活动详情。
6. 用户可以收藏、查看相关帖子、评论或发起找搭子。

### 场景 C：用户浏览兴趣社区

1. 用户点击底部“圈子”。
2. 默认进入“推荐”信息流。
3. 用户切换“关注”“关注的人”或“话题”。
4. 浏览活动体验、搭子回顾和活动评价帖子。
5. 用户可以点赞、评论、收藏、分享或关注作者。
6. 点击帖子中的活动标签进入活动详情。
7. 点击作者头像进入个人主页。
8. 点击发布按钮发布活动体验或找搭子需求。

### 场景 D：用户管理个人资料和历史关系

1. 用户进入“我的”。
2. 点击“编辑主页”，修改头像、昵称、个性签名、城市和兴趣标签。
3. 进入“我的活动”，查看计划参加、进行中、已完成和已取消的活动。
4. 进入“我的搭子”，查看聊天记录、历史搭子和共同参加次数。
5. 点击历史搭子，查看共同活动、公开帖子和评价标签。

### 场景 E：用户调整使用体验

1. 用户点击发现页右上角三横线。
2. 进入菜单。
3. 查看消息、活动提醒和收藏。
4. 打开夜间模式或护眼模式。
5. 调整字体大小、通知权限和个性化推荐。
6. 设置即时保存并影响整个 App。

## 3. 整体页面框架

```text
同场 App
├── 发现（底部导航 1）
│   ├── 搜索
│   ├── 活动分类：演唱会 / 展览 / Livehouse / 更多
│   ├── 热门活动轮播
│   ├── 活动推荐列表
│   ├── 活动详情
│   ├── 活动相关帖子
│   ├── 找搭子需求设置
│   ├── 匹配中
│   ├── 匹配结果
│   ├── 搭子详情
│   └── 聊天
│
├── 圈子（底部导航 2）
│   ├── 推荐
│   ├── 关注
│   ├── 关注的人
│   ├── 话题
│   ├── 帖子详情
│   ├── 评论列表
│   ├── 发布内容
│   ├── 用户主页
│   └── 匿名评价 / 标签
│
└── 我的（底部导航 3）
    ├── 个人主页
    ├── 编辑主页
    ├── 我的帖子
    ├── 我的收藏
    ├── 我的活动
    ├── 我的搭子
    ├── 评价和标签
    ├── 匹配偏好
    └── 设置
```

图片底部展示的 8 个核心页面对应如下：

```text
01 发现       = 活动入口、分类和推荐活动
02 活动详情   = 某一场活动的详细信息
03 找搭子     = 针对该活动设置需求
04 匹配中     = 系统匹配过程
05 匹配结果   = 该活动的推荐搭子列表
06 搭子详情   = 被选中的某位搭子资料
07 聊天       = 与该搭子沟通
08 我的       = 个人资料和活动记录
```

“圈子”是对原设计中第二个底部导航的功能扩展，不等同于“匹配结果”。

## 5. 发现首页内容结构

### 5.1 搜索栏

搜索支持：

- 演唱会名称。
- 展览名称。
- Livehouse 名称。
- 歌手或乐队。
- 场馆。
- 城市。
- 话题。

搜索交互：

1. 点击搜索栏进入搜索页。
2. 输入关键词后显示联想词。
3. 点击搜索提交结果。
4. 结果按“活动 / 帖子 / 用户 / 话题”分组。
5. 点击活动结果进入活动详情。
6. 点击帖子结果进入帖子详情。
7. 点击用户结果进入用户主页。
8. 无结果显示空状态和推荐搜索词。
9. 搜索历史可以删除。

### 5.2 活动分类

第一版固定展示：

```text
演唱会    展览    Livehouse    更多
```

点击行为：

- 演唱会：加载演唱会活动流。
- 展览：加载展览活动流。
- Livehouse：加载 Livehouse 活动流。
- 更多：打开分类面板。

“更多”第一版可包含：音乐节、话剧、脱口秀、艺术市集、电影放映。

切换分类后，活动轮播、活动列表、活动数量和活动帖子都必须同步变化。

### 5.3 热门活动轮播

轮播卡片包含：

- 活动图片。
- 活动类型。
- 活动名称。
- 时间和地点。
- 参与人数。
- 正在找搭子人数。
- 查看详情按钮。

交互：

- 每 4 秒自动切换。
- 支持左右滑动。
- 支持分页圆点点击。
- 手动滑动后暂停自动播放 5 秒。
- 点击卡片任意区域进入对应活动详情。
- 活动图片加载失败时显示占位图。

### 5.4 “今天，去哪里？”活动列表

列表支持上下滚动，第一版数据包括：

- 活动图片。
- 活动名称。
- 活动类型。
- 时间。
- 地点。
- 距离。
- 参与人数。
- 匹配人数。
- 收藏状态。
- 找同好按钮。

## 6. 各模块用途、第一版数据和操作

### 6.1 活动模块

**用途**：展示活动并作为找搭子流程入口。

**第一版必要数据**：

- `eventId`
- 名称
- 类型
- 封面图
- 时间
- 地点
- 城市
- 简介
- 活动标签
- 参与人数
- 正在找搭子人数
- 状态：即将开始 / 进行中 / 已结束 / 已取消

**第一版操作**：查看、搜索、筛选、收藏、分享、评论、我想去、找同好。

### 6.2 找搭子模块

**用途**：收集用户需求并生成活动内匹配结果。

**第一版必要数据**：

- 活动 ID
- 用户 ID
- 同行方式
- 社交状态
- 到场时间
- 关系期待
- 公开状态
- 创建时间
- 匹配状态

**第一版操作**：提交、返回修改、重新匹配、跳过、和 TA 同场、发起聊天。

### 6.3 搭子模块

**用途**：展示某位搭子的资料、共同经历和关系操作。

**第一版必要数据**：

- 用户资料
- 兴趣标签
- 个性签名
- 匹配百分比
- 共同活动次数
- 共同活动列表
- 公开帖子
- 关注状态
- 屏蔽状态

**第一版操作**：关注、发消息、和 TA 同场、查看共同活动、举报、拉黑、匿名评价。

### 6.4 圈子帖子模块

**用途**：形成活动后的持续交流和内容沉淀。

**第一版必要数据**：

- `postId`
- 作者 ID
- 内容类型
- 正文
- 图片或视频
- 关联活动 ID
- 话题 ID
- 点赞数
- 评论数
- 收藏数
- 发布时间
- 可见范围

**第一版操作**：发布、编辑、删除、点赞、评论、回复、收藏、分享、关注作者、不感兴趣、举报。

### 6.5 评论模块

**用途**：允许用户对帖子和活动交流。

**第一版必要数据**：评论 ID、作者 ID、帖子 ID、正文、回复对象、点赞数、时间、状态。

**第一版操作**：发表评论、回复、点赞、删除自己的评论、举报评论。

### 6.6 消息模块

**用途**：支持搭子之间持续沟通和同行确认。

**第一版必要数据**：会话 ID、参与者、消息 ID、消息类型、消息正文、活动卡片、发送时间、已读状态。

**第一版操作**：发送文字、发送活动卡片、发送图片、撤回、删除、标记已读、举报、拉黑。

### 6.7 个人主页模块

**用途**：管理个人身份、活动记录和社交关系。

**第一版必要数据**：头像、昵称、签名、城市、兴趣标签、背景图、帖子、收藏、活动记录、搭子关系。

**第一版操作**：编辑头像、昵称、签名、城市、兴趣标签、背景图和可见范围。

### 6.8 评价和标签模块

**用途**：记录同行体验，帮助系统改善匹配。

**第一版标签**：守时、好沟通、有共同兴趣、尊重边界、拍照技术好、临时放鸽子、沟通困难。

**第一版操作**：匿名提交、查看标签统计、申诉、隐藏评价。

### 6.9 设置模块

**第一版操作**：夜间模式、护眼模式、字体大小、通知设置、隐私设置、个性化推荐、清除缓存、备份和恢复。

## 7. 关键交互逻辑和页面反馈

### 7.1 搜索

```text
点击搜索 → 输入关键词 → 显示联想 → 提交搜索 → 显示结果 → 点击活动 → 活动详情
```

必须有：加载状态、无结果状态、搜索历史、删除历史、错误提示。

### 7.2 活动分类

点击分类后：

- 分类按钮进入选中态。
- 轮播内容更新。
- 活动列表更新。
- 页面标题和筛选条件更新。
- 无活动时显示该分类的空状态。

### 7.3 轮播推荐

自动切换时更新分页圆点；用户点击轮播卡片后进入该卡片对应的活动详情，不能固定跳到同一个活动。

### 7.4 三横线菜单

点击后打开半屏菜单；点击消息、设置、夜间模式或护眼模式必须产生页面或视觉变化；点击遮罩或返回按钮关闭菜单。

### 7.5 圈子信息流

- 推荐、关注、关注的人、话题是独立数据流。
- 点赞后图标和数字立即改变。
- 评论后新增评论并更新数量。
- 收藏后显示已收藏状态。
- 关注后作者进入关注流。
- 删除或举报后帖子从当前列表消失并显示提示。

### 7.6 活动匹配

- 匹配结果的每个用户有独立数据。
- 小满、阿树、Yuki 分别进入不同详情页。
- 每个人都有“和 TA 同场”按钮。
- 点击按钮后进入确认状态或聊天页。
- 重新匹配会生成新的结果或更新推荐顺序。

### 7.7 聊天

- 发送消息后立即出现在消息列表。
- 对方消息显示未读数量。
- 点击活动卡片回到活动详情。
- 发送“确认同行”后更新活动状态。
- 网络失败时消息显示发送失败，可重试。

### 7.8 我的活动和历史搭子

- 活动分为计划参加、进行中、已完成、已取消。
- 已完成活动可以发布回顾和评价搭子。
- 点击历史搭子进入搭子详情。
- 搭子详情显示共同活动次数和共同参加记录。

## 8. 本地数据保存、备份、恢复和更新

### 8.1 本地保存策略

第一版采用本地优先的可运行方案：

- 结构化数据保存到 IndexedDB。
- 小型设置保存到 localStorage。
- 图片和视频使用设备文件或浏览器缓存的引用。
- 所有记录带 `schemaVersion` 和 `updatedAt`。
- 每条本地数据使用稳定 ID，避免页面刷新后重复创建。

建议的数据集合：

```text
users
activities
events
posts
comments
conversations
messages
matches
relationships
notifications
settings
searchHistory
backupMeta
```

### 8.2 手机交互

- 首次打开初始化本地数据库。
- 刷新页面后保留登录状态、主题设置、收藏和草稿。
- 移动端支持触摸滑动、长按菜单、下拉刷新和上拉加载。
- 图片上传前压缩并显示进度。
- 离线时允许查看已缓存活动、帖子和聊天记录。
- 离线操作进入待同步队列，恢复网络后自动同步。

### 8.3 备份

设置中提供“导出我的数据”：

- 导出 JSON 数据。
- 可选择是否包含图片。
- 导出前显示数据范围。
- 生成带版本号和时间的备份文件。

### 8.4 恢复

设置中提供“导入备份”：

1. 选择备份文件。
2. 校验文件版本和完整性。
3. 显示将恢复的数据数量。
4. 用户确认后导入。
5. 冲突数据按更新时间处理。
6. 恢复完成后刷新页面并显示结果。

### 8.5 更新

- 读取本地 `schemaVersion`。
- 新版本启动时执行数据迁移。
- 迁移前自动创建本地快照。
- 迁移失败时回滚快照。
- 新版本显示更新说明。
- 删除旧数据前要求确认。

## 10. 验收标准

### 10.1 导航验收

- 底部只有“发现、圈子、我的”。
- 点击圈子后进入社交信息流，不进入匹配结果。
- 每个导航切换后保留正确的页面状态和滚动位置。

### 10.2 发现页验收

- 演唱会、展览、Livehouse 点击后显示不同活动内容。
- 更多可以打开更多活动类型。
- 搜索活动后显示对应结果。
- 点击搜索结果可以进入对应活动详情。
- 活动轮播会自动切换，手动点击可以进入不同活动详情。
- 活动列表可以滚动，卡片中的按钮可正常操作。

### 10.3 匹配流程验收

- 活动详情可以进入找搭子。
- 找搭子需求提交后进入匹配中。
- 匹配结果显示至少三位不同用户。
- 小满、阿树、Yuki 点击后进入各自详情。
- 三个人都有“和 TA 同场”按钮。
- 每个人都能进入独立聊天会话。

### 10.4 圈子验收

- 推荐、关注、关注的人、话题可切换。
- 帖子可以点赞、评论、收藏、分享和关注作者。
- 点击活动标签可以进入活动详情。
- 点击作者头像可以进入用户主页。
- 发布内容后帖子出现在个人主页和对应信息流。
- 删除、举报和不感兴趣后界面有明确反馈。

### 10.5 我的验收

- 可以修改头像、昵称、签名、城市和兴趣标签。
- 可以查看计划参加、进行中、已完成和已取消活动。
- 可以查看历史搭子和共同活动次数。
- 已完成活动可以发布回顾并提交匿名评价。

### 10.6 设置验收

- 三横线菜单可打开并关闭。
- 消息、活动提醒、收藏和浏览历史可进入对应页面。
- 夜间模式改变全局主题。
- 护眼模式改变色温和高亮对比度。
- 字体大小改变主要文字尺寸。
- 设置刷新页面后仍然保留。

### 10.7 数据验收

- 刷新页面后本地收藏、草稿、设置和历史记录仍存在。
- 可以导出备份文件。
- 可以导入备份并恢复数据。
- 数据版本升级时不会丢失已有记录。
- 迁移失败可以恢复到迁移前状态。

### 10.8 移动端验收

- 手机宽度下内容不横向溢出。
- 点击区域适合手指操作。
- 支持触摸滑动轮播和列表。
- 键盘弹出时输入框仍然可见。
- 网络失败、空列表和加载中都有明确页面反馈。

## 11. 开发顺序

1. 建立三栏导航和页面路由。
2. 完成发现页搜索、分类、轮播和活动列表。
3. 完成活动详情和找搭子流程。
4. 完成独立匹配结果、搭子详情和聊天。
5. 完成圈子信息流和帖子互动。
6. 完成发布内容和评论系统。
7. 完成我的主页、活动记录和历史搭子。
8. 完成消息菜单、主题、护眼和字体设置。
9. 接入本地 IndexedDB、备份、恢复和数据迁移。
10. 按验收标准进行手机端测试。

---

## 12. 版本范围结论

第一版必须让用户在手机上完成四件事：

1. 找到一个想参加的活动。
2. 找到并联系一位合适的搭子。
3. 在圈子里分享和互动。
4. 在我的页面管理自己的资料、活动和关系记录。

所有主要按钮都必须有对应的页面变化、状态变化或反馈提示，不能只做视觉上的装饰按钮。
