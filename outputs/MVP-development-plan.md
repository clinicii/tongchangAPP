# 同场 App 最小可运行 MVP 开发计划

- **依据文档**：[PRD.md](./PRD.md)
- **目标交付物**：一个可直接在手机浏览器打开运行的 `index.html`
- **开发方式**：单文件、前端本地运行、内置演示数据、无后端依赖
- **第一阶段目标**：验证信息架构、页面跳转、核心交互和本地数据保存

---

## 1. MVP 交付标准

MVP 必须能够在电脑浏览器和手机浏览器中直接打开，并完成以下闭环：

```text
发现活动 → 搜索/分类 → 活动详情 → 找搭子 → 匹配结果
→ 选择不同搭子 → 搭子详情 → 聊天 → 确认同行

发现 / 圈子 / 我的
→ 圈子信息流 → 点赞、评论、收藏、关注
→ 发布帖子

我的 → 编辑资料 → 活动记录 → 历史搭子
```

MVP 不依赖服务器、不需要安装构建工具、不需要账号登录即可演示。

---

## 2. 推荐技术方案

### 2.1 第一版技术选型

- HTML5：页面结构和路由容器。
- CSS3：手机布局、主题、轮播和响应式样式。
- 原生 JavaScript：状态管理、事件处理和页面切换。
- `localStorage`：设置、收藏、点赞、草稿和最近浏览。
- `IndexedDB`：帖子、评论、消息、活动记录和备份数据。
- JSON：内置活动、用户、帖子和匹配结果演示数据。

### 2.2 为什么先做单文件

- 用户可以直接双击打开。
- 不依赖 npm、服务器和数据库安装。
- 便于在手机浏览器快速验证。
- 后续可以把同一个文件拆分成 React/Vite 项目。

### 2.3 MVP 文件

```text
outputs/
└── index.html
```

第一阶段只要求一个入口文件。图片可以先使用渐变、占位图或远程图片地址，数据使用内置 JSON。

## 5. 核心交互实现计划

### 5.1 应用外壳

先实现：

- 手机最大宽度容器。
- 状态栏模拟。
- 顶部栏。
- 底部三栏导航：发现、圈子、我的。
- 全局返回按钮。
- 页面切换动画。
- 当前导航选中状态。

验收：任何主页面都能切换到三个底部导航，且不会刷新整个页面。

### 5.2 发现首页

实现顺序：

1. 顶部 Logo、消息按钮和三横线按钮。
2. 搜索框。
3. 活动分类：演唱会、展览、Livehouse、更多。
4. 热门活动自动轮播。
5. “今天，去哪里？”活动列表。
6. 活动收藏和找同好按钮。

交互要求：

- 分类切换后轮播和列表数据同步变化。
- 轮播每 4 秒自动切换。
- 点击轮播卡片进入对应活动详情。
- 点击活动卡片进入对应活动详情。
- 点击找同好进入对应活动的匹配流程。

### 5.3 搜索

实现顺序：

1. 点击搜索框进入搜索页。
2. 输入关键词。
3. 显示最近搜索和热门搜索。
4. 提交后显示活动、帖子、用户三个结果区。
5. 点击活动结果进入活动详情。
6. 保存最近搜索到 `localStorage`。

必须实现：

- 输入为空时显示热门搜索。
- 无结果时显示空状态。
- 删除单条搜索历史。
- 清空全部搜索历史。

### 5.4 活动详情

实现：

- 活动主图。
- 活动名称、类型、时间、地点和介绍。
- 收藏、分享、我想去、已参加。
- 相关帖子。
- 参与者头像。
- 找同好按钮。

交互：

- 收藏状态写入本地。
- 点击相关帖子进入帖子详情。
- 点击用户头像进入用户主页。
- 点击找同好进入匹配需求页。

### 5.5 找搭子、匹配中、匹配结果

需求页选项：

- 一起看演出 / 逛展 / 拍照 / 吃饭。
- 安静 / 聊天 / 拍照 / 都可以。
- 提前到 / 准时到 / 结束后。
- 普通搭子 / 兴趣交流 / 长期搭子。

点击“开始匹配”：

1. 保存需求到本地。
2. 显示匹配中页面。
3. 1.5 秒后进入匹配结果。

匹配结果必须显示三位不同用户：

- 小满。
- 阿树。
- Yuki。

每位用户必须有自己的：

- 头像。
- 兴趣标签。
- 个性签名。
- 匹配分数。
- 详情页。
- 和 TA 同场按钮。
- 独立聊天会话。

### 5.6 聊天

第一版支持：

- 文字消息。
- 活动卡片消息。
- 已读状态。
- 发送失败和重试。
- 确认同行按钮。

消息写入 IndexedDB。刷新页面后保留聊天记录。

### 5.7 圈子信息流

顶部频道：

```text
推荐 / 关注 / 关注的人 / 话题
```

实现：

- 帖子卡片。
- 点赞。
- 评论。
- 收藏。
- 分享。
- 关注作者。
- 活动标签。
- 话题标签。
- 发布按钮。

交互反馈：

- 点赞后图标变色、数量加一。
- 取消点赞后恢复。
- 收藏后显示“已收藏”。
- 关注后作者进入关注流。
- 点击活动标签进入活动详情。
- 点击头像进入用户主页。
- 点击评论打开评论弹窗或帖子详情。

### 5.8 发布帖子

第一版表单字段：

- 内容类型：活动体验 / 找搭子 / 搭子回顾。
- 正文。
- 关联活动。
- 话题。
- 可见范围。

点击发布后：

- 校验正文不能为空。
- 写入 IndexedDB。
- 返回圈子页。
- 新帖子出现在推荐流和我的帖子。
- 显示“发布成功”提示。

### 5.9 我的

实现：

- 头像、昵称、个性签名、城市、兴趣标签。
- 编辑主页。
- 我的帖子。
- 收藏。
- 我的活动。
- 历史搭子。
- 匹配偏好。

历史搭子详情显示：

- 共同参加过的活动。
- 共同活动次数。
- 聊天入口。
- 公开帖子。
- 匿名评价标签。

### 5.10 三横线菜单和设置

菜单打开后显示：

- 消息。
- 活动提醒。
- 收藏。
- 浏览历史。
- 夜间模式。
- 护眼模式。
- 字体大小。
- 个性化推荐。
- 通知设置。

第一版重点完成：

- 夜间模式切换全局主题。
- 护眼模式调整背景色温。
- 字体大小改变主要文字。
- 设置刷新后保持。

## 6. 文件实现计划

### 阶段 1：创建单文件骨架

建立：

```text
index.html
├── <style> 全部样式
├── <body> 手机页面容器
└── <script> 数据、状态、路由和交互
```

先完成空页面和主导航，不引入业务数据。

### 阶段 2：加入演示数据

在 `<script>` 中建立：

```js
const state = {
  route: 'home',
  activeTab: 'discover',
  activeCategory: 'concert',
  events: [],
  users: [],
  posts: [],
  messages: [],
  settings: {},
  searchHistory: []
};
```

所有页面从 `state` 渲染，不直接在多个页面中重复写死内容。

### 阶段 3：实现页面渲染函数

```js
renderApp()
renderHome()
renderSearch()
renderActivityDetail()
renderMatchForm()
renderMatching()
renderMatchResults()
renderCompanionDetail()
renderChat()
renderCircle()
renderPostDetail()
renderPostCreate()
renderProfile()
renderProfileEdit()
renderSettings()
```

### 阶段 4：实现事件和路由

统一使用：

```js
navigate('activity-detail', { eventId: 'event-001' })
```

所有按钮通过 `data-action` 或事件委托处理，避免在 HTML 中复制大量逻辑。

### 阶段 5：实现本地存储

- `localStorage`：设置、搜索历史、收藏状态、主题。
- `IndexedDB`：帖子、评论、消息、活动记录、备份。
- 启动时加载本地数据并合并演示数据。
- 退出或刷新前不需要手动保存，操作即时写入。

### 阶段 6：实现备份和恢复

第一版提供：

- 导出 JSON。
- 导入 JSON。
- 校验 `schemaVersion`。
- 显示导入数量。
- 导入前确认。
- 导入失败回滚。

### 阶段 7：手机端适配

检查：

- 320px、375px、390px、430px 宽度。
- 触摸点击区域至少 44px。
- 列表和轮播支持触摸滑动。
- 键盘弹出时输入框可见。
- 页面不出现横向滚动。

├── data/

拆分顺序：

1. 抽离静态数据。

6. 加入真实图片上传和内容审核。
7. 封装为 Android / iOS 应用。

## 11. 开发完成定义

当以下条件同时满足时，MVP 才算完成：

- 用户可以在手机上打开单文件并完成活动匹配闭环。
- 发现和圈子是两套独立的信息流。
- 搜索、分类、轮播、帖子、匹配、聊天和个人主页都能产生真实页面变化。
- 关键数据在刷新后仍然存在。
- 不同搭子、不同活动和不同帖子不会错误地跳到同一内容。
- 主要操作都有成功、失败、空状态和加载反馈。
- 通过上述验收清单。

## 13. 用户补充：活动数据数量和来源要求

首页活动列表必须支持向下滚动。第一版演示数据按三类分别准备至少 5 条：

- 演唱会：至少 5 条。
- 展览：至少 5 条。
- Livehouse：至少 5 条。

每条活动都必须包含：名称、类型、日期、场馆、城市、封面占位图、简介、参与人数、找搭子人数和活动状态。首页默认显示当前分类的完整列表，不能只显示一张活动卡。

本次 MVP 数据使用上海近期公开活动作为演示数据来源，并在代码中保留 `sourceUrl` 字段，便于后续核验和替换。演唱会和 Livehouse 数据可参考大麦、秀动等公开演出页面；展览数据可参考上海博物馆、浦东美术馆和上海市文化旅游部门的公开页面。活动日期和票务信息上线前仍需重新核验。
