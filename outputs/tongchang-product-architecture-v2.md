# 同场 App 产品级信息架构与交互规格 v2

## 0. 产品核心模型

同场不是单纯的活动列表，也不是单纯的聊天工具。产品由四类对象组成：

- **活动 Event**：演唱会、展览、Livehouse 等真实活动。
- **内容 Post**：用户发布的活动体验、现场记录、找搭子需求和评价。
- **搭子 Companion**：因为某场活动认识的人，可以持续聊天、再次约活动。
- **关系 Relationship**：关注、点赞、评论、聊天、一起参加活动、匿名评价和标签。

用户的主要路径是：

```text
发现活动 → 参加活动 → 找到搭子 → 一起参加 → 发布内容 → 形成长期搭子关系
```

## 1. 底部三栏的最终职责

### 1.1 发现：活动推荐信息流

“发现”不是只有分类按钮，而是以活动为中心的信息流。

顶部固定为：

```text
推荐    关注    关注的人    附近
```

每个频道都必须有内容：

- **推荐**：根据兴趣、城市、时间和浏览记录推荐活动。
- **关注**：用户关注的活动、兴趣话题和创作者发布的内容。
- **关注的人**：关注的人正在参加、推荐或评价的活动。
- **附近**：当前城市或附近区域的活动。

页面内容包括：

- 活动卡片
- 活动相关帖子
- 正在找搭子的人
- 活动热度和参与人数
- 用户关注的活动动态

发现页中的三个分类按钮必须切换真实数据：

```text
演唱会 → 演唱会活动流
展览 → 展览活动流
Livehouse → Livehouse 活动流
```

点击活动卡进入该活动的详情页；点击帖子进入帖子详情页；点击用户头像进入用户主页。

### 1.2 搭子：兴趣社区信息流

“搭子”是社区，不是匹配结果页。它类似小红书的信息流，核心是分享和关系建立。

顶部固定为：

```text
推荐    关注    关注的人    话题
```

页面内容包括：

- 活动体验分享
- 现场照片和短视频
- “这场演出值得去吗？”等讨论
- 找搭子帖子
- 与搭子一起参加活动后的评价
- 对某场活动的留言
- 对搭子的匿名评价和标签
- 兴趣话题内容

点击搭子导航后，默认进入“推荐”信息流，不进入“找到 3 位同场搭子”。

### 1.3 我的：个人关系和内容管理

“我的”必须是可编辑的个人主页，而不是只读资料页。

页面包括：

- 头像、昵称、个性签名、城市
- 编辑资料
- 我的帖子
- 我的收藏和点赞
- 我的活动
- 我的历史搭子
- 我的评价和标签
- 匹配偏好
- 隐私与通知设置

### 发现页按钮行为

| 控件 | 点击后行为 |
|---|---|
| 搜索框 | 进入搜索页，可搜活动、用户、帖子、话题 |
| 推荐/关注/关注的人/附近 | 切换对应信息流并保留滚动位置 |

| 分享 | 系统分享或复制活动链接 |
| 用户头像 | 进入该用户主页 |
| 找同好 | 进入该活动的找搭子流程 |
| 评论数量 | 进入该活动相关帖子和评论页 |

## 3. 活动详情页详细结构

```text
活动详情
├── 返回
├── 分享
├── 收藏
├── 活动主图 / 图片轮播
├── 活动名称、时间、地点
├── 活动介绍
├── 活动标签
├── 参与人数
├── 正在参加的人
├── 相关帖子
├── 我想去 / 已参加 / 不感兴趣
├── 找同好
└── 评论区
```

按钮逻辑：

- **我想去**：活动加入“我的活动·计划参加”，并允许创建找搭子需求。
- **已参加**：进入活动回顾，可发布体验和评价。
- **不感兴趣**：减少该类活动推荐。
- **找同好**：进入该活动专属匹配流程。
- **相关帖子**：进入该活动的帖子聚合页。
- **评论区**：可以查看、点赞、回复和发布活动留言。

## 4. 活动匹配流程

```text
活动详情
  ↓ 找同好
需求设置
  ├── 想怎么一起：看演出 / 逛展 / 拍照 / 吃饭 / 聊天
  ├── 社交状态：安静 / 聊天 / 拍照 / 都可以
  ├── 到场时间：提前 / 准时 / 结束后
  ├── 关系期待：普通搭子 / 兴趣交流 / 长期搭子
  └── 是否公开需求
  ↓ 开始匹配
匹配中
  ↓ 完成
匹配结果
  ├── 小满
  ├── 阿树
  └── Yuki
```

匹配结果中的每个用户都是独立对象：

- 点击用户卡片：进入该用户详情。
- 点击“和 TA 同场”：确认选择，并进入聊天或等待对方回应。
- 点击“跳过”：隐藏该推荐并加载下一位。
- 点击“换一批”：重新生成推荐。
- 点击“调整需求”：返回需求设置重新匹配。

## 5. 搭子详情和长期关系

### 搭子详情页

```text
搭子详情

├── 个性签名
├── 兴趣标签
├── 共同参加过的活动

├── 匹配百分比
├── 关注 / 取消关注
```

### 一起参加过的活动

用户可以点击“共同参加过的活动”，查看：

- 活动照片和相关帖子
- 双方是否互相评价
- 共同参加次数

## 6. 搭子社区信息流

### 帖子类型

- 活动体验：分享活动现场和感受。
- 活动评价：评价演出、展览或 Livehouse。
- 找搭子需求：公开寻找某场活动的同伴。
- 搭子回顾：与某位搭子一起活动后的记录。
- 话题讨论：围绕音乐、摄影、展览等兴趣交流。

### 帖子卡片内容

- 用户头像、昵称、发布时间
- 帖子正文
- 图片或视频
- 关联活动
- 关联话题
- 点赞数量
- 评论数量
- 收藏数量
- 分享按钮
- 关注用户按钮

### 帖子操作

| 操作 | 行为 |
|---|---|
| 点赞 | 点赞/取消点赞，更新数量 |
| 评论 | 打开评论页，可发布文字、回复评论 |
| 收藏 | 保存到“我的收藏” |
| 分享 | 复制链接或系统分享 |
| 关注 | 关注/取消关注作者 |
| 关联活动 | 进入活动详情 |
| 举报 | 选择原因并提交 |
| 不感兴趣 | 减少类似内容推荐 |

### 评论和评价

评论支持：

- 一级评论
- 回复评论
- 点赞评论
- 删除自己的评论
- 举报评论
- 评论中@用户

搭子评价支持匿名方式：

- 守时
- 好沟通
- 有共同兴趣
- 尊重边界
- 拍照技术好
- 临时放鸽子
- 沟通困难

匿名评价只显示统计标签，不公开评价者身份；被评价者可以查看标签统计并进行申诉。

## 7. 发布内容

搭子页右上角和底部悬浮按钮都可以进入发布页。

```text
发布
├── 选择内容类型
│   ├── 分享活动体验
│   ├── 发布找搭子需求
│   └── 发布搭子回顾
├── 输入文字
├── 添加图片 / 视频
├── 关联活动
├── 添加话题
├── 设置可见范围
│   ├── 所有人
│   ├── 关注的人
│   └── 仅自己
└── 发布
```

发布后：

- 内容出现在自己的主页。
- 根据活动和话题进入相关信息流。
- 关注者可以看到该内容。
- 用户可以编辑、删除或隐藏自己的帖子。

### 编辑资料

用户可以修改：

- 头像

- 城市
- 性别和年龄展示方式
- 兴趣标签
- 主页背景图
- 公开内容范围

### 我的活动

分为：

```text

```

- 活动信息
- 活动日期
- 同行搭子

### 我的搭子

分为：

- 最近聊天
- 一起参加过的搭子
- 互相关注
- 已屏蔽

点击某个搭子后可以查看：

- 聊天记录
- 一起参加过的活动
- 共同活动次数
- 共同帖子
- 评价标签
- 再次约活动

## 9. 消息系统

消息不是一次性页面，而是持续可用的功能。

```text
消息
├── 聊天列表
├── 单聊页面
│   ├── 发送文字
│   ├── 发送图片
│   ├── 发送活动卡片
│   ├── 发送位置或集合点
│   ├── 撤回消息
│   ├── 删除消息
│   └── 举报 / 拉黑
├── 活动群聊（可选）
├── 匹配通知
├── 评论和点赞通知
├── 关注通知
└── 系统通知
```

单聊中可以发送活动卡片，点击活动卡片回到活动详情；可以发送“确认同行”，对方接受后，活动状态更新为“已确认”。

## 10. 页面状态必须完整

每个信息流和列表都要处理这些状态：

- 加载中
- 空状态
- 无网络
- 加载失败
- 已刷新
- 没有更多内容
- 内容被删除
- 用户被拉黑
- 活动已结束
- 活动已取消

每个按钮也要有明确反馈：

- 点击态
- 成功提示
- 失败提示
- 需要登录提示
- 二次确认
- 不可用状态

## 11. 交互自查结果

本次整理后，以下逻辑已经分开：

- “发现”的活动推荐流和“搭子”的兴趣社区流是两套信息流。
- “推荐、关注、关注的人”在两个信息流中都有明确位置。
- “匹配结果”只从具体活动详情进入，不占用搭子导航。
- 每个匹配对象都有独立详情、按钮和聊天对象。
- Yuki 和其他推荐对象一样拥有“和 TA 同场”操作。
- 搭子可以发布内容、评论、点赞、收藏、关注和匿名评价。
- 用户可以编辑个人主页、查看历史活动和历史搭子。
- 历史搭子可以查看共同活动次数和共同内容。
- 聊天、活动卡片、评价和通知彼此连通。

## 12. 推荐的实现顺序

1. 先实现三栏主导航和两个独立的信息流。
2. 再实现活动列表、活动详情和活动分类切换。
3. 再实现找搭子、匹配结果和三位独立搭子详情。
4. 再实现聊天、活动卡片和同行确认。
5. 再实现帖子详情、评论、点赞、收藏和关注。
6. 再实现发布内容和活动回顾。
7. 最后实现个人主页编辑、历史活动、历史搭子和匿名评价。
